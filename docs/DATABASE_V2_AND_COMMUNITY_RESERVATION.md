# 乡遇数据库 V2 与留言板预留模块

## 更新目标

版本 1.9.6 在不改变现有离线使用方式的前提下，扩展服务端 PostgreSQL 数据库，为后续在线更新城市资料和建设留言板做准备。当前 APP 仍以内置的全国 337 个地级行政区资料为离线底座；数据库不可用时，小吃、风俗、景区、酒店、交通和避坑等现有功能不受影响。

## 城市内容数据库

Flyway 迁移 `V2__content_catalog_and_community_reservation.sql` 新增：

- `content_revisions`：记录每批城市内容的版本、说明和发布时间。
- `city_content_entries`：按地市代码和分类保存小吃、风俗、景区、酒店、交通、避坑条目。
- `content_change_seq`：为客户端后续增量拉取分配单调递增序号。

每条内容都保存标题、摘要、来源名称、来源链接、来源发布时间、扩展 JSON、排序、发布状态、版本和删除标记。只有经过核验并标记为 `PUBLISHED` 的条目才允许在后续公开接口中返回。

本次只建立数据库和版本边界，不把未经人工复核的网络抓取结果直接导入生产库，也不替换当前 APP 的离线数据。后续上线动态内容前，应完成导入工具、审核后台、来源有效性检查和客户端降级测试。

## 留言板预留模块

数据库预留以下表：

- `community_posts`：帖子与回复，支持城市和具体条目关联。
- `community_reports`：用户举报及处理状态。
- `community_moderation_events`：审核、隐藏、驳回、恢复和删除的审计记录。

留言正文限制为 1 至 2000 字；新内容默认进入 `PENDING_REVIEW`，不能直接公开。帖子写入使用 `author_user_id + client_request_id` 唯一约束，避免弱网重试产生重复内容。

## 默认关闭策略

- 服务端配置 `XIANGYU_COMMUNITY_ENABLED` 默认值为 `false`。
- 服务端当前仅提供只读状态接口 `GET /api/v1/community/status`，没有发帖、回复、列表或举报写接口。
- Android 端 `CommunityModule.CLIENT_RELEASE_ENABLED` 固定为 `false`，不显示留言板入口。
- 将来开放时，必须同时通过服务端功能开关和经过审核的客户端版本，单独修改一端不会误开放入口。

## 正式开放前的必要工作

1. 完成用户协议、隐私政策和社区规范更新，并在发帖前取得明确同意。
2. 建立内容安全审核、敏感信息过滤、举报处置、申诉和未成年人保护流程。
3. 增加发帖频率限制、账号风控、越权测试和垃圾信息防护。
4. 明确内容保存期限、注销后的处理规则和执法协查流程。
5. 完成应用备案及应用市场对用户生成内容功能的合规复核。
6. 通过灰度开关小范围验证后再逐步开放，不直接全量启用。

## 部署与回滚

服务启动时 Flyway 自动执行 V2 迁移。部署前应先备份 PostgreSQL，并在同版本测试库验证迁移。V2 只新增序列、表和索引，不修改 V1 用户、会话及个人同步表，不影响现有账号与同步数据。

Flyway 迁移已经执行后不要手工删除历史记录或修改校验和。若功能暂不启用，只需保持 `XIANGYU_COMMUNITY_ENABLED=false`；不应通过删除表来回滚。确需数据库结构回退时，应先停写并使用经验证的独立回退脚本和数据库备份。
